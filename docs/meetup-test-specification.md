# Meetup 기능 테스트 사양서

## 1. 개요

- 대상 기능: 항해(Meetup) 개설, 목록/상세 조회, 수정, 참여 신청
- 대상 화면: `/meetups`, `/meetups/create`, `/meetups/:meetupId`, `/meetups/:meetupId/edit`
- 대상 API
  | 구분 | Method | Path | 연결 상태 |
  | --- | --- | --- | --- |
  | 개설 | POST | `/meetup` | 연결됨 |
  | 수정 | PATCH | `/meetup/{meetup_id}` | 연결됨 (모임장만) |
  | 목록 | GET | `/meetup` | 연결됨 |
  | 상세 | GET | `/meetup/{meetup_id}` | 연결됨 |
  | 참여 신청 | POST | `/meetup/{meetup_id}/apply` | 연결됨 |

## 2. 테스트 환경 준비

1. BE 실행
   - 위치: `be`
   - 명령: `npm run dev`
   - 확인: `http://localhost:3000/ping` → `pong`
2. FE 실행
   - 위치: `fe`
   - 명령: `npm run dev`
3. 로그인 사용자 식별값 준비 (둘 중 하나)
   - 브라우저 콘솔: `localStorage.setItem('user_id', '테스트유저ID')`
   - `fe/.env.local`: `VITE_DEV_USER_ID=테스트유저ID`
4. DB에 위 사용자 ID가 실제로 존재해야 함 (모임 개설/수정/신청 시 조회됨)
5. CORS: BE는 기본적으로 `http://localhost:5173`을 허용하도록 설정되어 있어야 함

## 3. 공통 검증 규칙 (FE/BE 동일 기준)

| 항목 | 규칙 |
| --- | --- |
| 모집 인원 | 최소 4명 ~ 최대 8명, 최대 ≥ 최소 |
| 참여 금액 | 0 이상 정수 |
| 회차 수 | 정확히 4개 (개설 시 고정, FE에서 추가/삭제 불가) |
| 회차 필드 | `sch_date`, `sch_time`, `topic` 모두 필수 |
| 모집 마감일 | 현재 시각 이후 |
| `sch_day` | `sch_date` 기준 요일 자동 계산 (FE에서 생성) |
| `sch_st_time` | 입력한 `sch_time`과 동일 |
| `sch_ed_time` | `sch_st_time` + 2시간 (자정 초과 시 순환) |

## 4. 기능별 테스트 케이스

### 4.1 항해 개설 (POST /meetup)

경로: `/meetups/create`

| ID | 시나리오 | 사전조건 | 절차 | 기대 결과 |
| --- | --- | --- | --- | --- |
| CREATE-01 | 정상 개설 | 로그인 사용자 ID 준비됨 | 필수 정보 + 회차 4개(날짜/시간/주제) 입력 후 개설하기 클릭 | `/meetups`로 이동, 목록에 신규 항목 노출 |
| CREATE-02 | 회차 개수 고정 확인 | - | 생성 화면 진입 | 회차가 처음부터 4개로 표시되고 `+`/삭제 버튼이 없음 |
| CREATE-03 | 모집 인원 범위 오류 | - | 최소 3명 또는 최대 9명 입력 후 제출 | 화면에 "모집 인원은 4~8명" 문구 노출, API 호출 안 됨 |
| CREATE-04 | 회차 값 누락 | - | 특정 회차의 날짜/시간/주제 중 하나 비움 | "모든 회차의 날짜, 시간, 주제를 입력해 주세요." 노출 |
| CREATE-05 | 마감일 과거 입력 | - | 마감일을 오늘 이전으로 입력 | 제출 시 BE에서 400, 에러 메시지 화면 표시 |
| CREATE-06 | 로그인 ID 없음 | localStorage/`VITE_DEV_USER_ID` 미설정 | 정상 입력 후 제출 | "localStorage user_id" 관련 안내 메시지 노출, API 미호출 |
| CREATE-07 | 종료 시간 자동 계산 | 개발자도구 Console 오픈 | 특정 회차 시간 `20:00` 입력 후 제출 | 콘솔 로그 payload에서 `sch_st_time=20:00`, `sch_ed_time=22:00` 확인 |
| CREATE-08 | 자정 초과 종료 시간 | - | 회차 시간 `23:30` 입력 후 제출 | payload의 `sch_ed_time=01:30` 확인 |
| CREATE-09 | 요일 자동 계산 | - | 특정 날짜 입력 후 제출 | payload의 `sch_day`가 해당 날짜의 실제 요일과 일치 |

### 4.2 항해 목록 조회 (GET /meetup)

경로: `/meetups`

| ID | 시나리오 | 절차 | 기대 결과 |
| --- | --- | --- | --- |
| LIST-01 | 목록 정상 조회 | `/meetups` 접속 | 로딩 표시 후 DB 데이터 기반 목록 렌더링 |
| LIST-02 | 검색 필터 | 검색창에 제목/도서명 일부 입력 | 해당 키워드 포함 항목만 노출 |
| LIST-03 | 결과 없음 | 존재하지 않는 키워드 입력 | "검색 결과가 없습니다." 노출 |
| LIST-04 | 목록 조회 실패 | BE 중지 상태에서 접속 | "목록 조회에 실패했습니다." 및 에러 메시지 노출 |
| LIST-05 | 상태 뱃지 매핑 | 상태값이 다른 모임 확인 | RECRUITING/CLOSED → 승선 대기, IN_PROGRESS → 항해 중, COMPLETED → 입항 완료 |

### 4.3 항해 상세 조회 (GET /meetup/{meetup_id})

경로: `/meetups/:meetupId`

| ID | 시나리오 | 절차 | 기대 결과 |
| --- | --- | --- | --- |
| DETAIL-01 | 정상 상세 조회 | 목록에서 특정 항목 클릭 | 모임 정보, 회차, 통계 정상 표시 |
| DETAIL-02 | 존재하지 않는 ID | URL에 임의의 큰 숫자 meetup_id 입력 | "모임을 찾을 수 없습니다." 빈 상태 화면 노출 |
| DETAIL-03 | 참여 인원 통계 | 신청자가 있는 모임 조회 | 연령/성별/독서량 통계 영역 표시 |

### 4.4 항해수정 (PATCH /meetup/{meetup_id}) — 모임장 전용

경로: `/meetups/:meetupId/edit`

| ID | 시나리오 | 사전조건 | 절차 | 기대 결과 |
| --- | --- | --- | --- | --- |
| EDIT-01 | 수정 버튼 활성화 (모임장) | 로그인 ID == 모임 leader_id | 상세 화면 진입 | "항해수정" 버튼이 활성 링크로 표시 |
| EDIT-02 | 수정 버튼 비활성화 (비모임장) | 로그인 ID != 모임 leader_id | 상세 화면 진입 | "항해수정" 버튼이 비활성화(disabled) 상태로 표시 |
| EDIT-03 | 정상 수정 | 모임장 계정으로 로그인 | 수정 화면에서 항해명/소개/금액 변경 후 저장 | "모임 수정이 완료되었습니다." 메시지 노출 |
| EDIT-04 | 권한 없는 수정 시도 (API 직접 호출) | 다른 사용자 ID로 PATCH 요청 | Postman 등으로 직접 호출 | 403 응답, "모임 수정 권한이 없습니다." |
| EDIT-05 | 필수값 누락 | - | 항해명 또는 소개를 비우고 저장 | "항해명과 소개를 모두 입력해 주세요." 노출, API 미호출 |
| EDIT-06 | 참여 금액 오류 | - | 금액에 음수 입력 후 저장 | "참여 금액은 0원 이상 숫자로 입력해 주세요." 노출 |

### 4.5 항해 참여 신청 (POST /meetup/{meetup_id}/apply)

경로: `/meetups/:meetupId` 상세 화면 하단 바

| ID | 시나리오 | 사전조건 | 절차 | 기대 결과 |
| --- | --- | --- | --- | --- |
| APPLY-01 | 정상 신청 | 로그인 사용자 ID 준비, 미신청 상태 | "항해 참여하기" 클릭 | "항해 참여 신청이 완료되었습니다." 노출, 상세 데이터 재조회 |
| APPLY-02 | 로그인 ID 없음 | localStorage 비움 | "항해 참여하기" 클릭 | 안내 메시지 노출, API 미호출 |
| APPLY-03 | 중복 신청 | 이미 신청한 모임에서 재클릭 | 클릭 | BE 409 응답, "이미 신청한 모임입니다." 노출 |
| APPLY-04 | 모집 마감 모임 신청 | 상태가 RECRUITING이 아닌 모임 | 클릭 | BE 400 응답, "현재 모집중인 모임이 아닙니다." 노출 |
| APPLY-05 | 정원 초과 | 이미 정원이 가득 찬 모임 | 클릭 | BE 400 응답, "모집 인원이 마감되었습니다." 노출 |
| APPLY-06 | 신청 중 버튼 상태 | 네트워크 느린 환경 | 클릭 직후 상태 확인 | 버튼 비활성화 + "신청 중..." 텍스트 표시 |

## 5. 회귀 테스트 체크리스트 (배포 전 필수)

- [ ] BE 서버가 CORS 헤더를 포함해 정상 기동되는지 확인
- [ ] 개설 → 목록 반영 → 상세 조회 흐름이 끊기지 않는지 확인
- [ ] 모임장 계정과 비모임장 계정 각각으로 수정 버튼 활성/비활성 확인
- [ ] 동일 사용자가 같은 모임에 중복 신청 시 에러 처리 확인
- [ ] 개발자도구 Network 탭에서 각 API의 요청/응답 바디가 사양과 일치하는지 확인

## 6. 알려진 제한 사항 (테스트 시 참고)

- 로그인 화면은 아직 실제 인증 API와 연동되지 않아, 수동으로 `localStorage.user_id`를 설정해야 위 시나리오들을 테스트할 수 있음
- 회차는 개설 시 4개로 고정되며, 화면에서 4개 초과/미만으로 변경 불가
- 모집 인원은 4~8명 범위를 벗어나면 FE 단계에서부터 제출이 차단됨
