## 3. 기능 요구사항

### 3.1 회원 관리

#### REQ-MEM-001: 로그인 — 🔶 부분 구현

**요구**: 카카오 소셜 로그인. 비로그인 사용자가 참여 신청하면 로그인/회원가입 팝업 모달을 노출함.

**구현**

- 아이디·비밀번호 로그인 (`POST /auth/login`). 성공 시 JWT(유효기간 1일)와 회원 정보를 반환하고, 비밀번호 해시는 반환하지 않음.
- 아이디 또는 비밀번호가 틀리면 같은 401 메시지로 응답함 (계정 존재 여부 비노출).
- 비로그인 사용자가 "항해 참여하기"를 누르면 **로그인 화면으로 이동**하고, 로그인 후 원래 화면으로 돌아옴.
- 로그인이 필요한 화면(`RequireAuth`)은 비로그인 시 로그인 화면으로 보내고 원래 경로를 보관함.
- 토큰이 만료되면(401) 토큰을 삭제하고 로그아웃 처리한 뒤 로그인 화면으로 보냄.

**원본과 다른 점**: 카카오 로그인 없음(`user.social_provider`, `social_id` 컬럼만 준비됨). 팝업 모달 대신 화면 이동.

#### REQ-MEM-002: 회원가입 — ✅ 구현

**규칙** (BE·FE 동일)

| 항목      | 규칙                                                                               |
| --------- | ---------------------------------------------------------------------------------- |
| 아이디    | 영문+숫자 포함 4~10자, 중복 불가 (탈퇴한 아이디도 재사용 불가). 중복 확인 API 제공 |
| 비밀번호  | 영문+숫자 포함 8~64자, 비밀번호 확인 일치                                          |
| 이메일    | 형식 검사, 100자 이하, 중복 불가                                                   |
| 닉네임    | 1~50자                                                                             |
| 성별      | 남(`M`) / 여(`F`)                                                                  |
| 연령대    | 10대, 20대, 30대, 40대, 50대, 60대 이상 (가입 화면은 20대 이상만 선택 제공)        |
| 월 독서량 | 1~2권 / 3~4권 / 5~6권 / 7권 이상                                                   |
| 선호 장르 | 12종 중 **최대 2개**, 중복 불가                                                    |

**원본과 다른 점**: 아이디 항목이 추가됨. "좋아하는 책 종류"는 최대 2개(`genre_1`, `genre_2`). 비밀번호는 bcrypt로 저장함.

#### REQ-MEM-003: 마이페이지 — ✅ 구현

- **나의 항해 일지**: "크루로 참여한 모임" / "캡틴으로 만든 모임" 탭. 모임별로 로그북 작성·조회(크루) 또는 크루 로그북 확인(캡틴) 화면으로 이동함.
- **회원정보**: 조회·수정(닉네임, 이메일, 성별, 연령대, 독서량, 장르), 비밀번호 변경(현재 비밀번호 확인 필수). 처음에는 입력창 없이 **텍스트로 정보만 보이고**, "회원정보 수정" 버튼을 눌러야 입력창이 열림(취소하면 다시 텍스트로 돌아감).
- **회원탈퇴**: 비밀번호 확인 후 소프트 삭제. **진행 중(모집 중·마감·진행 중)인 모임의 캡틴이거나 크루이면 탈퇴 불가(409)**. 작성한 로그북·리뷰는 기록으로 남음.

**원본과 다른 점**: 신청 상태 값 `ING`/`COMPLETED` 중 `COMPLETED`는 코드 어디에서도 설정되지 않음. 종료 여부는 **모임 상태**(`COMPLETED`)로 판단함.

### 3.2 모임 생성 및 관리

#### REQ-GRP-001: 모임 등록 — 🔶 부분 구현

**규칙** (`POST /meetup`, 로그인 필수, 요청자가 캡틴이 됨)

| 항목          | 규칙                                                                                          |
| ------------- | --------------------------------------------------------------------------------------------- |
| 제목 / 도서명 | 필수. 각각 100자 / 150자 이하                                                                 |
| 소개          | 필수                                                                                          |
| 참여 금액     | 0 이상 정수 (단일 값)                                                                         |
| 모집 인원     | 최소 4명 ~ 최대 8명, 최소 ≤ 최대                                                              |
| 모집 마감     | 현재 시각 이후                                                                                |
| 회차          | **정확히 4개**. 회차 번호 중복 불가. 각 회차는 주제·날짜(YYYY-MM-DD)·요일·시작/종료 시간 필수 |
| Zoom          | URL·비밀번호는 회차별 저장. 등록 화면은 **하나만 입력받아 4개 회차에 동일하게 적용**          |
| 도서 이미지   | 파일 업로드(Blob) 또는 이미지 URL 직접 입력                                                   |

**이미지 업로드** (`POST /meetup/book-image`, 로그인 필수): jpeg·png·webp·gif만 허용, 10MB 이하. Azure Blob에 저장하고 **공개 URL을 반환·저장**함. 이미지가 아니면 400, 용량 초과면 413.

**원본과 다른 점**: 카테고리, 도서 상세 내용 없음. 회차는 "4~6회차"가 아닌 4회차 고정. 화면의 "납부 방법" 선택값은 **서버로 전달·저장되지 않음**.

#### REQ-GRP-002: 모임 목록 조회 — 🔶 부분 구현

**구현**

- `GET /meetup` (비로그인 허용): 페이지·개수(최대 100)·검색어(제목)·상태 필터, 최신순 정렬.
- 카드에 **도서 이미지, 모임명, 도서명, 인원, 일정, 상태**를 표시함. 이미지가 없으면 기본 이미지를 사용함.
- 상태 표기: `RECRUITING` → "승선 대기", `CLOSED` → "승선 마감", `IN_PROGRESS` → "항해 중", `COMPLETED` → "항해 완료". 마감 일시가 지난 `RECRUITING`은 배치 반영 전에도 "승선 마감"으로 표시하고, 상세 화면의 참여 버튼은 "승선 대기"일 때만 활성화함.

**원본과 다른 점 / 문제**

- 홍보 문구는 카드에 표시하지 않음.
- **목록 화면이 첫 페이지(10건)만 불러오고 페이징·무한 스크롤 UI가 없음.** 검색도 불러온 10건 안에서만 동작함. (8장 P0)
- 정렬 기준은 원본에서 "확인 필요"로 남아 있어 최신순으로 구현함.

#### REQ-GRP-003: 모임 상세 조회 — 🔶 부분 구현

**구현** (`GET /meetup/:id`, 비로그인 허용)

- 표시: 도서 이미지, 모임명, 캡틴, 소개, 참여 금액, 인원(신청 수/최대), 모집 마감, 회차별 주제·날짜·시간.
- **멤버 통계 도넛 차트**: 신청자의 연령대·성별·독서량 분포.
- 로그북 제출 안내 영역 표시.
- 하단 버튼: 목록으로 / 항해수정(캡틴만 활성) / 항해 참여하기(캡틴 본인은 비활성).

**원본과 다른 점**: 월 금액·납부 방법(고정 문구 "일시납")·장소(고정 문구 "장소 안내 예정")·환불 안내가 실제 데이터가 아님. 모임 경험 수 통계, 추천 모임 3개 없음(추천 영역은 빈 상태).

#### REQ-GRP-004: 모임 정보 수정 — ✅ 구현

- `PATCH /meetup/:id`: 캡틴만 가능(다른 사용자 403). 제목·소개·이미지·금액·회차 정보를 수정함.
- 비어 있는 제목·소개·도서명으로는 수정할 수 없음. URL과 본문의 `meetup_id`가 다르면 400.

#### REQ-GRP-005: 신청자 목록 조회 — 🔶 부분 구현

**구현**

- `GET /member/meetups/:id/crews`: 캡틴만 조회. 신청자 ID·이름·참여 상태.
- 회차별 제출 현황(`GET /logbook/.../sessions/:id`): **미제출 크루까지 포함**해 제출 완료/미제출/확인 완료를 구분하고 로그북 본문을 화면에서 읽을 수 있음.

**원본과 다른 점**: 성별·독서량·신청일자를 반환하지 않음. 독후감 다운로드 기능 없음.

### 3.3 모임 신청 및 결제

#### REQ-PAY-001: 참여 신청 및 결제 — 🔶 부분 구현 (결제 미구현)

**구현** (`POST /meetup/:id/apply`, 로그인 필수)

- 신청하면 `apply` 행이 `ING` 상태로 생성되고, 내 항해 일지에서 확인함.
- 신청 불가 조건: 캡틴 본인(400) / 모집 중이 아니거나 마감일 경과(409) / 이미 신청함(409) / 정원 초과(409) / 없는 모임(404).
- 동시 신청에 대비해 모임 행을 잠그고 같은 트랜잭션에서 처리함.

**원본과 다른 점**: 결제창(페이게이트) 연동, 결제 상태 관리, 환불 불가 안내가 모두 없음.

#### REQ-PAY-002: 모집 마감 자동 처리 — 🔶 부분 구현

- **즉시 마감**: 신청으로 최대 인원이 차면 같은 트랜잭션에서 `CLOSED`로 변경.
- **배치 마감**: 10분마다 실행. 모집 마감일이 지났거나 신청 수(삭제된 신청 제외)가 최대 인원 이상인 `RECRUITING` 모임을 `CLOSED`로 변경함. 여러 번 실행해도 결과가 같음.
- **모임 시작**: 첫 회차 날짜(KST)가 오늘 이전·당일인 `RECRUITING`·`CLOSED` 모임을 `IN_PROGRESS`로 변경함. 모집 마감일이 첫 회차보다 늦게 잡힌 모임도 시작일에 항해 중이 되며, 이후에는 신청할 수 없음.

**원본과 다른 점**: "최소 인원 충족 시 마감" 조건이 없음. 마감일에 **최소 인원(4명)에 못 미쳐도 그대로 진행됨**. 정책 결정이 필요함(9장).

### 3.4 과제 및 온라인 모임 운영

#### REQ-SES-001: 과제 안내 메일 — ✅ 구현

- **매일 09:00 KST** 실행. 3일 뒤(KST)에 열리는 `SCHEDULED` 회차 중 **진행이 확정된 모임(`CLOSED`·`IN_PROGRESS`)** 의 신청자 전원에게 발송함. 모집 중인 모임과 취소된 회차는 제외함.
- 본문: 모임명, 회차 주제, 일정, **제출 기한(모임 2일 전)**.
- 이메일이 없는 신청자는 건너뛰고, 한 명의 발송 실패가 나머지를 막지 않음. 실패가 있으면 API가 500으로 응답해 스케줄러가 실패로 기록함.

#### REQ-SES-002: 독후감(로그북) 작성 — 🔶 부분 구현

**구현**

- 크루가 회차마다 로그북 제출(`PUT`)·조회·수정·삭제. 같은 회차에 다시 제출하면 **덮어쓰고 확인 완료 상태를 해제**함.
- **화면 구성**: "로그북 작성" 탭에는 모든 회차가 아니라 **다음 예정 회차(오늘 KST 이후 첫 번째 취소되지 않은 회차) 하나와 그 로그북 입력창만** 보임. 모든 회차가 지났으면 "작성할 회차가 없어요"로 안내함. 지난 회차의 로그북은 "제출한 로그북" 탭에서만 확인함.
- **제출한 로그북 모아보기** (`GET /logbook/mine`): 여러 모임에서 제출했다면 **모임 단위로 묶고** 그 안에서 회차 순으로 보여줌(최근 제출한 모임이 먼저). **읽기 전용**이며 수정·삭제는 "로그북 작성" 탭의 해당 회차에서만 가능함. 삭제된 모임·회차의 로그북은 제외함.
- 삭제한 로그북을 다시 제출하면 같은 행을 복구해 덮어씀.
- 모임 크루만 제출 가능(아니면 403). 다른 모임의 회차(404), 취소된 회차(409)에는 제출할 수 없음.
- 작성 화면에 글자 수를 표시함.

**원본과 다른 점**: **400자 이상 검증, 모임 2일 전 제출 마감, .txt 파일 업로드가 없음.** 빈 문자열만 거부함. (8장 P0)

#### REQ-SES-003: 숙제 확인 완료 승인 — ✅ 구현 (이번 개정에서 추가)

- `PATCH /logbook/meetups/:id/sessions/:id/logbooks/:id/approval` (캡틴만, 다른 사용자 403). 본문 `{ "is_approved": true | false }`, 생략하면 승인.
- **제출된 로그북만** 승인 가능(미제출 409). 이 모임·회차의 로그북이 아니면 404. 확인 중 재제출과 겹치지 않도록 행을 잠금.
- 캡틴 화면(크루 로그북 확인)에 **"숙제 확인 완료 / 확인 취소"** 버튼과 "확인 완료" 배지를 표시함.
- 크루가 수정본을 다시 제출하면 승인이 풀려 **다시 확인을 받아야 함**.

**원본과 다른 점**: "400자 미만 표시" 기능은 SES-002의 400자 검증과 함께 미구현.

#### REQ-SES-004: Zoom 접속 정보 메일 — ✅ 구현

- **매일 08:00 KST** 실행. **제출 완료 + 캡틴 확인(승인) 완료**한 크루에게만, **모임 1일 전과 당일**(KST 오늘~내일) `SCHEDULED` 회차의 Zoom URL·비밀번호를 메일로 발송함. 매일 실행하면 회차당 정확히 2번(D-1, D-day) 발송됨.
- 미제출·미승인 크루, 2일 이상 남은 회차, 지난 회차는 제외함.
- Zoom URL·비밀번호·이메일 중 하나라도 비어 있으면 발송하지 않고 건너뜀.
- 한 명의 발송 실패가 나머지를 막지 않음. 실패가 있으면 500으로 응답해 스케줄러가 실패로 기록함.
- **승인 즉시 발송되지 않고 다음 배치 시각(08:00 KST)에 발송됨.**

#### REQ-SES-005: 온라인 모임 진행·입장 — 🔶 부분 구현

- 확정된 크루가 메일로 받은 Zoom 링크로 입장함. 모임 진행 자체는 Zoom에서 이루어짐.
- 캡틴이 모임을 "시작"하거나 회차를 수동으로 완료하는 기능은 없음. 회차 상태는 배치가 변경함.

### 3.5 후기 및 배치 처리

#### REQ-REV-001: 모임 후기 관리 — ✅ 구현

- **종료(`COMPLETED`)된 모임**에서 **크루만** 작성 가능. 모임당 1개. 별점 1~5(정수) + 내용 필수.
- 조회: 모임의 캡틴과 크루. 수정·삭제는 본인 후기만. 삭제 후 다시 작성하면 같은 행을 복구함.
- 진행 중인 모임(409), 이미 작성함(409), 별점 오류(400), 크루가 아님(403).

**원본과 다른 점**: 홈 화면의 후기 영역은 **실제 데이터가 아닌 샘플 문구**임.

#### REQ-BAT-001: 회차·모임 완료 자동 배치 — ✅ 구현

모든 날짜 판단은 **한국 시간(KST)** 기준임. 서버(UTC)에서도 같은 결과를 냄.

| 배치      | 동작                                                                                                                              |
| --------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 회차 완료 | 진행일이 **오늘(KST)보다 이전**인 `SCHEDULED` 회차를 `COMPLETED`로 변경 (진행일 익일 처리)                                        |
| 모임 완료 | 마지막 회차(취소 회차 제외) 날짜가 오늘(KST)보다 이전인 `CLOSED`·`IN_PROGRESS` 모임을 `COMPLETED`로 변경. 회차가 없는 모임은 제외 |

### 검증하지 못한 항목

- **실제 SMTP 메일 발송** (설정 없음)
- **실제 Azure Blob 업로드** (운영 스토리지 쓰기 테스트 권한 없음 — 배포 후 화면에서 확인 필요). E2E의 모임 개설은 로컬에 Azure 자격 증명이 없어 이미지 URL 직접 입력으로 대체함
- **E2E는 로컬 환경 한정**: 배포된 Azure(staging·SWA)에 대한 E2E, 모바일 화면, Chromium 외 브라우저는 검증하지 않음
- **Azure Functions 타이머의 실제 실행 시각**

### 배포 후 확인 순서

1. BE·FE 워크플로 성공 확인 (테스트 실패 시 배포 중단).
2. staging 슬롯에서 로그인 → 이미지 업로드 → 응답 URL(`https://stasharestory.blob.core.windows.net/images/...`) 확인 후 **슬롯 스왑**.
3. `functions-batch` 재배포 후 타이머 첫 실행과 `BATCH_API_KEY` 확인.
4. SMTP 설정 후 테스트 모임으로 "제출 → 승인 → Zoom 메일" 흐름 확인.
